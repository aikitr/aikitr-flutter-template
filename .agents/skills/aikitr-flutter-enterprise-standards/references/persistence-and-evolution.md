# 2. 缓存、持久化与数据演进

## 数据策略契约

每种持久化数据有 owner、权威来源、作用域、schema、保留/删除策略及失败语义。Repository 暴露业务读取策略，缓存与数据库细节不出现在页面。

| 类型 | 权威来源 | 故障默认处理 |
| --- | --- | --- |
| 可再获取缓存 | 后端/所属数据源 | 允许丢弃并重取；受隐私和离线策略约束 |
| 草稿与离线 outbox | 本地保存事实；提交结果仍由服务端确认 | 保全并提供恢复/重试，不当作缓存随意清除 |
| 主题等偏好 | 用户选择 | 回退默认值且说明写失败；非关键持久化 |
| 会话凭据 | 认证协议/安全存储 | 按会话协议失效或恢复；避免悄悄重建旧会话 |

## 缓存与失效

每类缓存声明：key（环境/账号/租户/查询/schema）、TTL、允许 stale 的最长时间、内存/磁盘容量、淘汰策略、失效事件、并发请求合并与错误行为。不要给整个 App 一个永久缓存策略。

- 区分 cacheOnly、networkOnly、cacheFirst、staleWhileRevalidate 等实际需要的策略；接口说明旧值何时可显示，刷新失败是否保留。
- 查询缓存可以容忍短暂 stale，库存、价格、授权与支付结果仍需服务端确认；不能以 TTL 未到为由跳过关键授权。
- 以绝对时间记录到期并处理设备时钟变化；安全过期/授权不能只信任客户端时钟。测试可注入时钟。
- 刷新与重复查询合并；取消一个 UI 消费者不能错误取消其他消费者共享的任务。
- 达到容量/磁盘限制时优先淘汰可重建数据，不能删除 outbox；图片缓存同时考虑下载字节和解码后尺寸。
- mutation 成功后按实体/查询依赖失效，使用 version/ETag 等协议时明确比较策略。退出和租户切换失效对应 namespace，不误删其他合法账号数据。

## schema 与迁移

数据库、草稿、缓存 envelope、outbox 和凭据格式分别声明 schema version 与最小可读取版本；应用版本号不能代替数据版本。迁移由所属 data/storage adapter 执行，业务模型负责约束，页面不执行 SQL/修复。

迁移链明确起止版本、前置条件、事务/检查点、数据校验、失败恢复和兼容窗口。数据库支持事务时把 schema/data/version 更新作为一个事务；例如 SQLite 的事务能力见 [官方说明](https://www.sqlite.org/lang_transaction.html)。不把所有存储引擎都假设成事务数据库。

长迁移采用引擎支持的可恢复策略和显式进度，避免无限阻塞启动；checkpoint 在成功提交后更新。多个 engine/isolate 访问时设置单写者/锁协议，其他消费者不能读取半迁移结构。

新版本读取旧 schema：按已验证迁移升级。旧版本遇到新 schema：仅当声明兼容时读取，否则拒绝该数据操作、提示升级或走经过验证的兼容路径；**禁止自动删库、盲目降版本号或破坏性重建**。App 回退与数据库回退分别评估。

可重建缓存迁移失败可按策略重建；不可替代草稿/outbox 迁移失败要保全。需要备份时验证引擎一致性、恢复流程、空间与数据保护；复制正在写入的文件不等于一致备份。密钥轮换需明确双读/迁移/旧密钥销毁和中断策略，不能在数据可读性确认前删除旧密钥。

协议模型新增字段、状态或版本时在 mapper 明确处理；缓存版本必须与解析器语义兼容。远程开关切换解析器不能把同一缓存 key 当作另一格式读取。

## 写入、删除与用户反馈

关键写入用已选择存储的原子/事务能力。偏好插件的多个独立键不提供跨键事务保证；需要一致性的数据放一个有版本的记录或适当数据库。

需要恢复的外部副作用遵守 [先保存操作记录、再发送](runtime-lifecycle.md)；operation ID、请求快照与发送状态具有一致性。服务端成功但本地确认写失败时保留未确认记录并查询结果，不重新生成幂等键。

明确“已保存本地”“等待同步”“已确认”的区别。磁盘满、损坏、设备锁定或权限变化必须形成可操作失败，不能返回成功。外部网络不能作为本地数据库事务的一部分，使用 outbox/协议协调。

删除动作记录涉及的本地缓存、凭据、草稿、服务器数据和备份范围；失败部分可重试，幂等，不因删除记录失败让旧数据在重启后悄悄恢复。数据保留与删除规则结合 [隐私规范](privacy-and-dependencies.md)。

## 验收

owner 保存旧 schema fixture 与迁移矩阵，至少覆盖：最旧支持版本逐步升级、每个迁移步骤中断、空间不足、损坏记录、多实例访问、新 schema 被旧客户端读取、迁移后数量/金额/幂等键不变、删除失败、缓存到期/时钟变化、账号隔离。

CI 执行 fixture 的升级及完整性测试；真实存储/密钥保护策略由设备验收。发布前说明无法支持的数据降级路径和用户恢复方式，不能以“本地数据可清理”为默认解决方案。
