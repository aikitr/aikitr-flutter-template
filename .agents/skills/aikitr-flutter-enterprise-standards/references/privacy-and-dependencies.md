# 6. 隐私、第三方 SDK 与依赖治理

## 数据分类与生命周期

团队使用一致分类，例如 public、internal、personal/confidential、restricted。分类决定采集、展示、缓存、备份、日志、导出和删除规则；具体监管/商店要求由负责人员结合产品地区核验，不把通用模板当作法律结论。

数据目录记录：字段/来源、业务目的、最小范围、owner、数据分类、保存位置、访问主体、上传对象、授权/合法依据核验、保留期、删除方式及备份策略。敏感数据不能仅因“便于排错”进入遥测。

账号散列、设备/广告标识及可关联事件不默认视为匿名；删除账号流程明确本地、服务端、第三方处理方和备份的范围。失败有可查询状态与重试，不以 UI 隐藏账号替代实际删除。

## SDK 采集边界

新增/升级 SDK 前评估：初始化默认采集、网络目的地、字段与权限、device ID/追踪、后台行为、数据处理方、保留期、许可证及平台隐私声明。隐私声明、App Store 填报与实际采集一致。

需要授权后采集的 SDK，在授权条件满足前不能自动初始化采集、缓存待上传个人事件；区分技术初始化与采集启用。拒绝/撤回后停止相应采集并处理已排队数据，恢复状态也不能越权。

授权按业务目的、字段范围和声明版本记录 revision；撤回先关闭内存采集门禁并使在途初始化/上传 generation 失效，再持久化拒绝或 revocation tombstone。清理 SDK 自身队列、缓存身份和相关本地事件，已上传数据按适用删除协议处理。禁用/清理失败保持采集关闭并提供可重试状态；拒绝状态持久化失败不得宣称撤回已可靠保存，启动无法确认授权时保持关闭。晚到初始化不能重新启用 SDK，重启不能恢复旧授权。

本地写入全部失败时，不能保证跨进程记住撤回。需要该保证的采集协议采用每次会话确认或启动核验权威授权 revision，验证不可用则关闭；不能只凭仍可读取的旧 grant 自动恢复采集。

SDK 版本或远程设置改变采集字段/目的地时重新核验。通过测试环境捕获受控网络/事件证据；仅检查包装层的 logger 不覆盖 SDK 自身采集。阻止未知 metadata 自由透传，不向所有插件共享完整会话对象。

新增字段/目的地超出原授权范围时不能沿用旧 scope。授权生命周期由所属业务契约管理，app 装配连接 SDK adapter，观测层消费受控门禁；不把整份会话或所有授权状态复制到每个插件。

iOS 检查 App 与相关 SDK 的 PrivacyInfo.xcprivacy、required-reason API 和适用 SDK 签名要求；打包后检查实际 archive，而不只阅读 pubspec。要求与清单实施时核验，依据 [Apple 数据用途文档](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests)、[第三方 SDK 要求](https://developer.apple.com/support/third-party-SDK-requirements/)。

## 依赖清单与供应链

维护直接/传递依赖、来源、解析版本、许可证、维护状态、原生平台要求、用途与 owner。清单覆盖 pub 包以及实际存在的 CocoaPods/SPM/Gradle 等原生依赖；SBOM 可由已验证工具生成，不能只列手写直接依赖。

依赖锁文件和发布产物对应；hosted content hash、固定 Git commit、插件原生变更与 CI action 都可审查。升级单独附兼容测试、隐私/权限/包体变化与回退条件，不随手允许任意 source override。

漏洞扫描先核验所用工具支持的生态、锁文件与传递深度；GitHub 上某项检查“通过”不证明全部 Dart/原生依赖被扫描。对不支持的生态记录补充检查与盲点，不能把无结果当作无漏洞。参考 [GitHub dependency graph](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/explore-dependencies) 的生态说明。

许可证检查按组织允许名单与分发方式评估；未知许可证不是自动放行，也不机械把所有开源许可证判为禁止。维护失活/不兼容平台的依赖有替换或 fork owner，fork 保留上游更新与安全维护路径。

## 风险处置、例外与权限

发现风险记录 advisory、影响版本、可达路径、数据/用户影响、现有控制、owner、修复方案和期限。基于严重度与实际暴露设响应时限；在未确认可利用时也保留依据，不靠“客户端不是服务器”忽略问题。

无法立即升级时记录短期控制、验证、批准 owner、到期与关闭条件，按 [例外模板](../assets/templates/exception-record.yaml)。缺少负责人/有效期的永久忽略不得进入 CI；过期阻断，紧急续期是新的有记录决策。

签名/部署/配置变更采用最小权限、分离不可信 PR 与发布环境、可撤销凭据；证书轮换及离职/泄露处置有明确 owner。扫描、通知、issue 创建或生产控制操作需对应任务授权，技能不会自动向外部系统提交信息。

## 验收

测试：授权前/拒绝/撤回/重启后的 SDK 行为，撤回与初始化/上传/重启竞争、拒绝记录保存与 SDK 禁用/清理失败，新增字段与目的地，日志与备份泄漏，账号删除失败，所有适用生态扫描覆盖，许可证未知情况，原生 archive 中隐私清单、漏洞/例外过期。

release checklist 附必要证据与未覆盖部分；保留受控样本，避免把真实用户数据作为测试 fixture。安全/隐私 owner 与模块 owner 共同管理变更，项目风险不同可以采用不同流程，但数据用途与权限边界必须明确。
